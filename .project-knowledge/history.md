## Fixed

- **Local media never plays on Linux (Study videos, music, subtitles) — player spins forever** → three-layer diagnosis: (1) not the file (system `gst-launch playbin` plays it), (2) not the GStreamer env (system WebKit plays it via `file://`), (3) isolated harness proved WebKitGTK's media loader never consults registered URI schemes — its GStreamer src element makes a real HTTP request, so Tauri's `http://asset.localhost` asset URL dies instantly (nothing listens) with FormatError before any pipeline builds; only `<img>`/page resources go through the scheme handler, which is why thumbnails worked. Fix: the local bridge now serves media — `media_stream_url` command mints an unguessable 6-hour single-file grant, `GET /media/{token}` streams with full Range/206 support and CORS; frontend `mediaSrc()` helper routes video/audio/subtitles through the bridge on Linux only (Windows/macOS keep convertFileSrc). Call sites: watch page, PlayerShell subtitles, music player store, file-clip. Frontend 582 tests + svelte-check green; 18 bridge tests green. Branch `fix/webkitgtk-media-bridge` (c9899013), stacked on the gst + keyring branches. *(fixed: 2026-09-30)*
- **Blank page when opening any media (Study tab course click)** → the AppImage bundles GStreamer's core libraries but no plugins, so WebKit's media player could not find `appsink`/`autoaudiosink`/`decodebin`, connected signals to NULL GObjects (GLib-GObject-CRITICAL) and the WebKitWebProcess SIGABRT'd, blanking the page. Fix in `main.rs setup_environment()`: inside an AppImage, set `GST_PLUGIN_PATH` (additive, never overriding a user choice) to the AppDir's (empty) plugin dir plus the system `/usr/lib[/64]/gstreamer-1.0` — ABI-compatible because the bundled libs are the same gst the system plugins were built against. Same signature explains the 04:15 login-time blank window. Branch `fix/appimage-gstreamer-plugins` (0cd20087), stacked on `fix/keyring-runtime-panic`. *(fixed: 2026-09-30)*
- **zbus runtime-in-runtime panic killed keyring access on every launch** (v0.10.0's new Linux keyring backend) → the sync `keyring` API on Linux is `async-secret-service` over zbus, whose blocking wrapper `block_on`s the calling thread; from a tokio worker (every async Tauri command) that panics `Cannot start a runtime from within a runtime` and kills whichever task touched a secret (AI keys, OmniDisc, profile seed). Journal showed it firing on every launch since the 0.10.0 build. Fix: the three raw keyring calls in `secrets.rs` now run on a dedicated OS thread (`off_runtime`) where no runtime exists; all 10 secrets tests pass. Branch `fix/keyring-runtime-panic` (e8742fbf). *(fixed: 2026-09-30)*
- **Launcher showed "A Tauri App" as the app description** → the AppImage's embedded desktop file is correct (Comment/GenericName/Categories from the post-SEO Cargo description), but Gear Lever's generated `~/.local/share/applications/omniget.desktop` was written when the AppImage still carried the create-tauri-app default `description = "A Tauri App"` (changed upstream in c9709621 "docs(seo)") and never refreshed when the AppImage was updated in place. Fix: rewrote the Gear Lever entry with the real metadata + `%u` in Exec (deep links), backup at `omniget.desktop.bak-20260930`. A Gear Lever "reinstall" would regenerate its own version. *(fixed: 2026-09-30)*
- **Updater signing key required for every source build** → defaulted `bundle.createUpdaterArtifacts` to `false` in `tauri.conf.json`, re-enabled only for tagged releases via `TAURI_CONFIG` in `release.yml` (PR #290). Verified: `pnpm tauri build --bundles deb` succeeds with no signing env vars. *(fixed: 2026-08-16)*
- **pnpm onlyBuiltDependencies in wrong file (PR #290)** → `pnpm` field in `package.json` is dead config on pnpm 10; author relocated to `pnpm-workspace.yaml` in PR #294, now upstream. *(fixed: 2026-08-16, relocated upstream: 2026-08-17)*
- **linuxdeploy AppImage bundling failed** (strip + missing FUSE) → worked around locally with `APPIMAGE_EXTRACT_AND_RUN=1` and by running appimagetool directly on the assembled AppDir; produced working `~/OmniGet.AppImage`. *(fixed: 2026-08-16, workaround only)*
- **AppImage couldn't run without FUSE2** → worked around with `--appimage-extract-and-run` / libfuse2 note. *(fixed: 2026-08-16)*
- **Gear Lever failed to install OmniGet AppImages** (`AttributeError: 'NoneType' object has no attribute 'get'`) → tauri-bundler 2.10.0 created **absolute** `.desktop`/`.DirIcon` symlinks in the AppDir; Gear Lever extracts with 7z, which turns absolute links into dangling ones, so no desktop entry is found. Root fix: bump `@tauri-apps/cli` to ^2.11.4 (upstream PR #15596 makes both symlinks relative). *(fixed: 2026-08-22)*
- **linuxdeploy strip failure on `.relr.dyn`** (supersedes the 2026-08-16 appimagetool workaround) → linuxdeploy's bundled `strip` is too old for DT_RELR sections in current Arch libs and any strip failure aborts bundling. Proper fix: `NO_STRIP=1`, set by the new `pnpm tauri:appimage` script and in `release.yml`. Fresh linuxdeploy downloads don't help — upstream still bundles old binutils. *(fixed: 2026-08-22)*
- **Tauri GTK plugin fails on Arch** (`cp: cannot stat '/usr/lib/gdk-pixbuf-2.0/2.10.0'`) → Arch ships gdk-pixbuf with loaders built in but stale pkg-config paths; plugin `copy_tree` + cache write then fail under `set -e`. Fix: vendored patched plugin at `scripts/linux/linuxdeploy-plugin-gtk.sh` (skip missing sources, mkdir -p before loaders.cache), auto-synced to `~/.cache/tauri/` by `pnpm tauri:appimage`. *(fixed: 2026-08-22)*

## Decisions

- **`createUpdaterArtifacts: false` as repo default** — source builders shouldn't need maintainer secrets; releases opt back in via env config instead of the committed file. Keeps the runtime updater pubkey in config so installed apps still verify updates. *(2026-08-16)*
- **pnpm approval committed to `pnpm-workspace.yaml`** rather than `package.json`/`.npmrc`/interactive — makes installs deterministic under pnpm 10. (Note: `package.json` `pnpm` field is dead config on pnpm 10.29.3.) *(2026-08-16)*
- **`.project-knowledge/` left untracked** — this clone's `origin` is the upstream repo we PR into; knowledge files must not leak into the PR branch. *(2026-08-16)*
- **AppImage packaging fixes live in-repo** (`pnpm tauri:appimage` wrapper + vendored GTK plugin + desktop template) instead of manual appimagetool post-processing — reproducible for anyone building on Arch, no extra manual steps. Desktop template also gives the AppImage proper `Categories=Network;FileTransfer;`. *(2026-08-22)*
